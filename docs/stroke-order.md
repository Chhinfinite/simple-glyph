# 笔顺与字形：为什么先确认字

## 1. 单字识别不能只靠 OCR

OCR 返回的是“候选字符串”，不是结构证据。  
「史」和「央」都是 5 笔，结构相近；在毛笔/艺术字里，外轮廓可能更像对方。

本项目的选择：

1. 先让用户确认字；
2. 再查公开笔顺；
3. 最后才进入几何提取。

如果字不确定，宁可停下来问，也不要把错字做成一套很漂亮的矢量。

## 2. 央的笔顺

`央` = 冂 + 大，标准顺序：

| 序号 | 笔画 | 说明 |
|---|---|---|
| 1 | 竖 | 左边短竖 |
| 2 | 横折 | 上横 + 右竖，草书里是连着的 |
| 3 | 横 | 口下的长横 |
| 4 | 撇 | 顶部中心竖向下，穿口，再向左下撇 |
| 5 | 捺 | 右侧向右下的捺 |

关键点：**顶部中心的长竖不是第 1 笔**，它属于第 4 笔「撇」。  
如果把长竖当第 1 笔，后面 4 笔的起笔点都会错位。

参考：

- 古诗句网：<https://www.gushiju.net/zidian/bishun/%E5%A4%AE>
- Hanzi Writer：<https://cdn.jsdelivr.net/npm/hanzi-writer-data@2.0.1/%E5%A4%AE.json>

## 3. 史与央的区别

| 字 | 结构 | 关键差异 |
|---|---|---|
| 史 | 口 + 乂 | 口比较完整，长横从口中穿过，下面是撇/捺 |
| 央 | 冂 + 大 | 上面是冂（开口向下），中心竖属于撇，长横在口下 |

这次项目里先判成「史」，用户纠正为「央」。  
错误原因：只看了“5 笔 + 中间竖 + 长横 + 左右腿”的粗略结构，没有确认冂的开口和中心竖归属。

## 4. 标准骨架能做什么，不能做什么

Hanzi Writer 的 `medians` 提供：

- 笔顺；
- 每笔的拓扑；
- 一个标准楷体的中心线先验。

它**不提供**：

- 你这张图的起笔/收笔；
- 折角的实际角度；
- 枯笔、飞白、粗细变化；
- 书法风格。

所以路线是：

```text
标准 medians（顺序/拓扑）
  + 目标图的 ink mask（几何）
  + 人工折角修正
  = 可用的中心线
```

不是“把标准字帖直接铺上去”。

## 5. Hint 的写法

- 每笔 3–6 个点；
- 起笔、折角、收笔各一个；
- 点落在笔画内部，不要压在边缘；
- 交叉处不要放太多点，避免 BFS 被带到邻笔；
- 先跑一遍，看 overlay，再微调。

一个 hint 示例：

```json
{
  "id": "4",
  "label": "撇",
  "waypoints": [[360, 40], [362, 150], [372, 300], [365, 400], [300, 500], [120, 710]]
}
```
